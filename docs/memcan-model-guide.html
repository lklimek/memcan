MemCan model guide — 8 GB & 16 GB VRAM

Which local model should
remember for you?

MemCan gives Claude Code persistent memory across sessions — a small local AI model reads your conversations and decides what's actually worth saving. We benchmarked the two leading options for that job, qwen3.5:9b and gemma4:26b-a4b-it-qat, on real engineering conversations, run through MemCan's actual production code (not a synthetic scoring rig). Here's what to pick — on an 8 GB card or a 16 GB one.

Short version qwen fits comfortably on an 8 GB card and is the only option if that's what you have. gemma4 is more accurate and more reliable, but needs a full 16 GB card to itself.

Rule #1: does it even fit?

Whether or not the model is actively "thinking," it has to sit fully loaded in your graphics card's memory (VRAM). This is the hard constraint everything else is downstream of — check it against your own card, whether that's 8 GB or 16 GB.

gemma4 is technically a 26-billion-parameter model that only "activates" about 4B of those parameters per response (that's why it isn't much slower) — but the full 26B still has to be sitting in memory, all the time. On a 16 GB card, that leaves almost nothing for anything else — no browser tabs eating GPU memory, no second model, no game in the background. On an 8 GB card it simply won't load. Pull the text-only build below to make sure every byte of that 16 GB actually lands on the GPU.

The 16 GB pick just got better

Ollama unconditionally tries to GPU-offload gemma4's vision projector — even though MemCan is text-only and never sends it a single image.

On a 16 GB card, that reserved-but-unused projector pushed some of the text model's own MoE-expert layers onto CPU too — the stock gemma4:26b-a4b-it-qat measured only ~87% GPU residency there. lklimek/gemma4-text:26b-a4b-it-qat strips the unused projector at the manifest level — same text weights, byte-identical Google QAT checkpoint, Q4_0 storage — and measured 100% GPU residency on the same card, with cold-load time dropping from 56–75s to ~7.6s. Same quality, no downside: this is now the default MemCan pulls, and the recommended way to run gemma4 on any GPU. recommended default

What about the writing itself?

We also compared how clearly each model summarizes what it saves — is it accurate, well-phrased, free of invented detail? Genuine tie. Both write comparably clear, faithful notes on real-world input. If good prose is all you care about, it isn't the deciding factor here — VRAM and reliability are.

So, which one?

Choose qwen3.5:9b if —

  • You're on an 8 GB card — gemma4 doesn't fit there at all
  • Your 16 GB card is shared with games, a browser, or other local AI tools
  • A bit more junk occasionally slipping into memory is an acceptable trade

Choose lklimek/gemma4-text:26b-a4b-it-qat if —

  • You have a full 16 GB card (not 8 GB) free for this
  • Accuracy and reliability matter more than squeezing into a smaller card
  • This is the default — the text-only build, so it lands at 100% GPU residency
